# ENDES data preparation plan

Mental Health and Internet Access Peru project

20 November 2026 · Source delivery `endes-2016-2017-full-intake-2026-11-20-v1`

## Goal and scope

The first block in [1 Data Preparation.do](../../../1%20Code/1%20Data%20Preparation.do) will validate the available official ENDES files and produce one survey-only working dataset at `3 Data/2 Working/ENDES_coded.dta`. Its row is one selected health respondent in a survey wave. It will retain the survey observations and the flags needed to reproduce analysis samples. Later source-specific blocks will prepare the broadband roster, service histories and other inputs separately, then link across sources. The ENDES block ends before cross-source exposure assignment or estimation.

Use 2016–2025 as the candidate main survey series and 2015 as a separately flagged sensitivity. Start implementation with the fully inventoried 2016 and 2017 releases. Widen it only after the two-wave acceptance checks pass. Preserve the frozen seven- and nine-wave runs and their existing replay commands. Earlier rounds are out of scope. Implementation and any changes to empirical eligibility, exposure or release require the coauthors' decisions under the project workflow.

## 3. Harmonize the survey variables and flags

- [ ] Create a wave-by-variable crosswalk with the exact instrument text or reference, Spanish labels, routing, native code and type, common value, missing-value reason, units and role. Record source page and variable name for each core field. Compare later waves field by field against the 2016–2017 map. Use the available 2020 routing and interview-mode materials, and hold any unresolved comparability choice for coauthor review before selecting a main sample.
- [ ] Preserve age, sex, final interview result, questionnaire version or mode, department and the original health weight. Generate age and residence flags using documented codes. Confirm `QS23` and `HV025` against the instruments and check disagreement with roster demographics where the measures are comparable. Report separate unknown, out-of-range and ineligible counts. Keep children and older respondents in the working spine if present and use age 15–29 for the research eligibility flag.
- [ ] Preserve `QS700A`–`QS700I` and distinguish a valid zero response, routed skip, missing answer, refusal and unexpected raw value wherever the instrument supports those distinctions. Generate the score only when all nine items have valid 0–3 codes. Assert the score is 0–27, a complete record has nine valid items and the sum agrees with an independent calculation. Report item availability and routing by wave, age band, residence and interview mode as appropriate. Keep the approved nine-item definition in the baseline and document changes separately if the coauthors approve any.
- [ ] Record the selected-person survey weight under a common variable with the raw value, native field and scale preserved, including `PESO15_AMAS` in the later waves and `PESO15_AJUS` in 2015. Check positive, zero, missing and outlying values. Retain native PSU and stratum fields such as `HV001`, `HV022`, `HV023` and `QHCLUSTER` with source labels. Verify the correct PSU and stratum for the health file and construct wave-qualified IDs only when supported by the design. Keep rescaling, survey configuration and treatment clustering decisions explicit for the later analysis.
- [ ] Construct the final health interview day and month using `QSINTD`, `QSINTM` and `QSINTY` after checking `QSRESULT` and the instruments. Use exact dates only for verified valid day-month-year triples, and keep month-only observations explicitly marked. Retain survey wave separately from calendar year. Audit day/month heaping, route-specific missingness, impossible dates and interviews outside documented fieldwork windows, including 2025-wave records in early 2026. The 2016 and 2017 input checks parsed the literal day, month and year on all released health rows. Check timing, routing and visit status independently. Preserve day precision even when the baseline uses month. Report timing flags and by-wave counts before any exposure-date comparison.
- [ ] Normalize the native household internet question `SH61Q` only after checking coding, unit and routing by wave. Preserve original values and the reason a common value is missing. This variable measures household-reported access. The later broadband block supplies project designation and evidence of operational service.
